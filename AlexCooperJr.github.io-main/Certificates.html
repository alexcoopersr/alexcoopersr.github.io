Lab 2 • Removing a pop-up

Disbale a "nag" screen

This case involved a case where a "nag" screen would repeatably pop-up on the GUI. This closely mirrors some behavior of real world malware that renders a device unusable due to constantly blocking the screen. This screen is diabled with two methods in this lab

To solve this issue one thing to do is the use a debugger like "OllyDbg" to break the code into its assembly instructions. By identifying the memory address associated with the stack frame creation we can use a "ret 4" instruciton to skip the body of the nags recurrsive call body. This disables the pop-up.

The other method involves brute forcing a password. Malicious users may request some compenensation for this password to disable the pop-up, but we will dig through the code to find it. Within the assembly instructions a string comp is found. By analyzing this we can figure that whatever is being compared to should be the correct password. Turning the byte code into unicode reveals the code and this can be immediately typed into the pop-ups field.

What I took away
  • Practice reading assembly instructions
  • The idea that a malware can have multiple solutions
  • The solution to a malware related issue is as simple as using bad coding practices on bad actors

Lab 8 • Gadgets & Return Oriented Programming (ROP)

Using stack overflow in tandem with gadgets for a multi-step exploit

To begin this lab we do the same steps as the previous lab and find the offset pattern we will need to model the payload. We essenitally want to use some built in gadget, which are remenants from the original code to cause unintended effects. ROP finds us using the return addresses of gadgets to jump around the code and call methods in a stack.

An important gadget is one that can pop things off the stack then return to a designated area. In the case of this lab it was also key to have a gadget that could spawn a shell to give us access over the system. With a carefully crafted payload of offset, gadgets, and a shell spawning method we can gain escalated privileges.

What I took away
  • Information and practice with gadgets and ROP
  • Further practice with stack overflow and payload creation
  • practice with gdb tool and tools for binary analysis

Lab 9 • Multi-Stage Attacks

Combining code analysis, overflow, gadgets/ROP, and elf to make an exploit chain.

This lab explorers the combination of all previous lab tasks with a new elf method to develop a longer true multi-stage exploit. This lab begins with vulnerbility analysis checking for any developer left bad practices. We then search for our shell spawning method in this case a "ed" string for a system call (ed is a linux cli editor). We then use the same methods as before to create a stack overflow, and craft a gadget/ROP payload.

With a lengthy payload crafted we also add a calculation that will find us system calls. We will find the base address for a system call by calulating an offset and adding that to our found base. This gives us access to a real time means of finding dynamically assigned system call.

With access to the shell we can capture the flag with a cat of the flag.txt file.

What I took away
  • Sharpened skills crafting a payload to accomdate multiple methods
  • Used elf files for exploit
  • First hand experience with flag capturing

Lab 11 • Final CTF

Combining everything (except the rootkit) to capture a flag

This final lab had some unique protections to test our analysis and critical thinking skills. One was NX being enable which protects the stack from having code executed right on it. This stack also had a canary which can act as an indication that overflowing is being attempted and terminates the program before that can happen.

This exploit was similar to lab 4 but with the additional steps of needing to leak the canary address. By leaking some information we could dynamically assign the canary values and ensure we could work around the protection. By placing the leaked canary value we can still cuase the desired overflow, do some ROP and chain a payload together before using a system call to get a shell. Thus allowing us to cat the flag and see a nice image of Pikachu.

What I took away
  • New topics with real world protections like Stack Canaries
  • Continued exploration of stack overflow, ROP, and payload creation
  • Crictal thinking about a plan of action
  • Reflection on everything learned from lab 6-11
